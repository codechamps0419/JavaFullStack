🌟 Core Spring Boot Annotations
@SpringBootApplication
Meta-annotation combining three powerful annotations: @Configuration (bean definitions), @EnableAutoConfiguration (smart defaults), and @ComponentScan (finds components). @SpringBootApplication is a key annotation that is used to mark the main class of a Spring Boot application and it eliminates boilerplate configuration. 🚀
@EnableAutoConfiguration
Enables Spring Boot's auto-configuration magic. Analyzes classpath and automatically configures beans. Uses @Conditional annotations internally. Can exclude specific configs with exclude attribute. 💡
@Configuration
Marks class as configuration source. Contains @Bean methods. Spring creates CGLIB proxy for singleton behavior. Replaces XML configuration. Use for Java-based configuration. ⚙️
@ComponentScan
Scans packages for Spring components. Finds @Component, @Service, @Repository, @Controller. Default: scans current package and sub-packages. Can specify basePackages or basePackageClasses. 🔍
@Bean
Method-level annotation in @Configuration classes. Manually creates and configures beans. Use for third-party classes or complex initialization. Method name becomes bean name (can override). Returns object managed by Spring.
🎯 Stereotype Annotations ~ Tell Spring exactly what role that class plays
@Service
Business logic layer annotation. Specialization of @Component. Indicates service layer class. No additional behavior, purely semantic. Best practice for service classes containing business logic. 💼
@Repository
Data access layer annotation. Specialization of @Component. Provides automatic exception translation - converts database exceptions to Spring's DataAccessException. Use for DAO/Repository classes. 🗄️
@Controller
Web MVC controller annotation. Handles HTTP requests and returns view names (HTML pages). Used with @RequestMapping. Returns ModelAndView or view name String. For traditional web applications. 🎨
@RestController
RESTful web service controller. Combines @Controller + @ResponseBody. All methods return data (JSON/XML) instead of views. No need for @ResponseBody on each method. Perfect for REST APIs.
@Component
Generic stereotype annotation. Marks class as Spring-managed component. Auto-detected by component scanning. Base annotation for @Service, @Repository, @Controller. Use when class doesn't fit above stereotypes. 🧩
💉 Dependency Injection
@Autowired
Automatic dependency injection. Can be used on constructor, setter, or field. Constructor injection is recommended. Spring resolves dependencies by type. Optional with required=false. ✨
@Qualifier
Specifies which bean to inject when multiple bin candidates exist. Works with @Autowired. Uses bean name to resolve ambiguity. Example: @Qualifier("userService"). Prevents NoUniqueBeanDefinitionException. 🎯
@Primary
Marks preferred bean when multiple beans of same type exist. Spring injects this bean by default. Alternative to @Qualifier. Only one @Primary per type. Useful for default implementations. ⭐
@Value
Injects values from properties files or environment. Supports SpEL expressions.
Syntax: @Value("${property.name}")
Can provide default: @Value("${name:defaultValue}").
Used for Simple property injection. 📝
@ConfigurationProperties
Type-safe configuration properties binding. Binds external properties to POJO. Prefix-based: @ConfigurationProperties(prefix="app").
Supports validation with @Validated. Better than multiple @Value for grouped properties. 📦
🌐 Web & REST Annotations
@RequestMapping
Maps HTTP requests to handler methods. Can specify path, method, params, headers. Works at class and method level. Base for all mapping annotations. Example: @RequestMapping(value="/users", method=RequestMethod.GET). 🗺️
@GetMapping
Shortcut for @RequestMapping(method=GET). Retrieves resources. Idempotent and safe. Used for read operations. Example: @GetMapping("/users/{id}"). More readable than @RequestMapping. 📥
@PostMapping
Shortcut for @RequestMapping(method=POST). Creates new resources. Non-idempotent. Typically used with @RequestBody. Returns 201 Created on success. Example: @PostMapping("/users"). ➕
@PutMapping
Shortcut for @RequestMapping(method=PUT). Updates entire resource. Idempotent. Replaces existing resource completely. Example: @PutMapping("/users/{id}"). Use PATCH for partial updates. 🔄
@DeleteMapping
Shortcut for @RequestMapping(method=DELETE). Deletes resources. Idempotent. Returns 204 No Content typically. Example: @DeleteMapping("/users/{id}"). Handle 404 if resource doesn't exist. 🗑️
@PatchMapping
Shortcut for @RequestMapping(method=PATCH). Partial resource updates. Non-idempotent. Updates only specified fields. Example: @PatchMapping("/users/{id}"). More efficient than PUT for partial changes. ✏️
@RequestBody
Binds HTTP request body to method parameter. Uses HttpMessageConverter (Jackson for JSON). Automatic deserialization. Add @Valid for validation. Example: @RequestBody User user. Required by default. 📨
@ResponseBody
Writes return value directly to HTTP response body. Bypasses view resolution. Uses HttpMessageConverter for serialization. Automatic with @RestController. Returns JSON/XML based on Accept header. 📤
@PathVariable
Extracts values from URI template. Example: /users/{id} with @PathVariable Long id. Required by default. Can specify name: @PathVariable("userId"). Use for resource identification. 🛣️
@RequestParam
Extracts query parameters from URL. Example: /users?name=John with @RequestParam String name. Optional with required=false. Can set default: @RequestParam(defaultValue="10"). Use for filtering/pagination. ❓
@RequestHeader
Extracts HTTP header values. Example: @RequestHeader("Authorization") String token. Access custom headers. Can be optional. Useful for authentication, content negotiation, API versioning. 📋
🔐 Security & Validation
@Valid
Triggers JSR-303 validation on request body. Works with validation annotations like @NotNull, @Size. Throws MethodArgumentNotValidException on failure. Use with @RequestBody for input validation. Ensures data integrity. ✅
@Validated
Spring's validation annotation. Supports validation groups. Can be used at class level for method validation. More flexible than @Valid. Enables @Validated on service layer for business validation. 🛡️
@NotNull
Validates field is not null. Part of Bean Validation API. Allows empty strings. Use for mandatory fields. Example: @NotNull(message="Name is required"). Works with @Valid or @Validated. 🚫
@NotEmpty
Validates collection or string is not null and not empty. Size must be greater than 0. Use for collections, arrays, strings. More strict than @NotNull. Example: @NotEmpty List items. 📝
@NotBlank
Validates string is not null, not empty, and contains non-whitespace characters. Trims whitespace before validation. Most strict for strings. Use for text inputs. Example: @NotBlank String username. 💬
@Size
Validates size of string, collection, array, or map. Specify min and max: @Size(min=2, max=50). Works on length for strings, element count for collections. Example: @Size(min=8) String password. 📏
@Min / @Max
Validates numeric values have minimum or maximum value. @Min(18) for age validation. @Max(100) for percentage. Works with Integer, Long, BigDecimal. Example: @Min(value=0, message="Price must be positive"). 🔢
@Email
Validates string is valid email format. Uses regex pattern internally. Checks for @ symbol and domain. Example: @Email String email. Can customize with regexp attribute for stricter validation. 📧
@Pattern
Validates string matches specified regex pattern. Example: @Pattern(regexp="^[0-9]{10}$") for phone numbers. Flexible for custom validation rules. Use for format validation like SSN, postal codes. 🎭
💾 Data & JPA Annotations
@Entity
Marks class as JPA entity mapped to database table. Each instance represents a table row. Must have @Id field. Table name defaults to class name. Use @Table to customize. Managed by EntityManager. 🗃️
@Table
Specifies table name and schema for entity. Example: @Table(name="users", schema="public"). Optional - defaults to entity class name. Can specify indexes and unique constraints. Use for custom table mapping. 📊
@Id
Marks field as primary key. Required for every @Entity. Can be simple (single field) or composite. Use with @GeneratedValue for auto-generation. Example: @Id private Long id. 🔑
@GeneratedValue
Specifies primary key generation strategy. AUTO (default), IDENTITY (auto-increment), SEQUENCE (database sequence), TABLE (separate table). Example: @GeneratedValue(strategy=GenerationType.IDENTITY). Database handles ID generation. 🎲
@Column
Customizes column mapping. Specify name, length, nullable, unique. Example: @Column(name="email_address", unique=true, nullable=false). Optional - defaults to field name. Use for fine-grained control. 📋
@Transactional
Manages database transactions declaratively. Automatic commit on success, rollback on exception. Can specify propagation, isolation, timeout, readOnly. Works at class or method level. Ensures data consistency. 🔄
@Query
Defines custom JPQL or native SQL query. Example: @Query("SELECT u FROM User u WHERE u.email = ?1"). Use nativeQuery=true for SQL. More flexible than method name queries. Supports named parameters. 📝
@Modifying
Indicates query modifies data (UPDATE/DELETE). Must be used with @Query. Requires @Transactional. Clears persistence context after execution. Example: @Modifying @Query("DELETE FROM User u WHERE u.active = false"). ✏️
⚡ Async & Scheduling
@Async
Executes method asynchronously in separate thread. Returns void, Future, or CompletableFuture. Requires @EnableAsync on configuration class. Non-blocking execution. Use for long-running tasks. Configure thread pool for better control. ⚡
@EnableAsync
Enables asynchronous method execution support. Place on @Configuration class. Activates @Async annotation processing. Can customize executor with AsyncConfigurer. Enables parallel processing capabilities. 🔛
@Scheduled
Schedules method execution at fixed intervals or cron expression. Example: @Scheduled(fixedRate=5000) or @Scheduled(cron="0 0 * * * *"). Requires @EnableScheduling. Use for periodic tasks like cleanup, reports. ⏰
@EnableScheduling
Enables scheduled task execution support. Place on @Configuration class. Activates @Scheduled annotation processing. Creates background task scheduler. Essential for time-based automation. 📅
🎪 Exception Handling
@ControllerAdvice
Global exception handler for all controllers. Centralizes exception handling logic. Use with @ExceptionHandler methods. Can specify basePackages to limit scope. Returns view names for traditional MVC. 🎯
@RestControllerAdvice
Global exception handler for REST APIs. Combines @ControllerAdvice + @ResponseBody. Returns JSON/XML error responses. Use for RESTful error handling. Example: return ErrorResponse object with status, message, timestamp. 🚨
@ExceptionHandler
Handles specific exception types. Place in @ControllerAdvice or controller. Example: @ExceptionHandler(ResourceNotFoundException.class). Can handle multiple exceptions. Returns custom error response with appropriate HTTP status. 🛠️
🧪 Testing Annotations
@SpringBootTest
Loads complete application context for integration testing. Starts embedded server if webEnvironment specified. Use for end-to-end tests. Can mock beans with @MockBean. Slower than slice tests but tests full integration. 🧪
@WebMvcTest
Tests only web layer (controllers). Loads only MVC components, not services or repositories. Faster than @SpringBootTest. Use with @MockBean for dependencies. Example: @WebMvcTest(UserController.class). 🌐
@DataJpaTest
Tests JPA repositories with in-memory database. Auto-configures H2, configures Hibernate, scans @Entity classes. Transactional by default (rollback after each test). Use for repository layer testing. 💾
@MockBean
Creates and injects Mockito mock into application context. Replaces existing bean or adds new one. Use in tests to mock dependencies. Example: @MockBean UserService userService. Automatically reset after each test. 🎭
@Test
Marks method as JUnit test case. Method must be public void with no parameters. Test runner executes these methods. Can use assertions to verify behavior. Part of JUnit 5 (Jupiter). ✅
@BeforeEach
Executes before each test method. Use for test setup and initialization. Creates fresh state for each test. Example: initialize test data, create mocks. Ensures test isolation. 🔧
@AfterEach
Executes after each test method. Use for cleanup and resource release. Runs even if test fails. Example: close connections, delete test files. Maintains clean test environment. 🧹
🎨 Conditional Annotations
@ConditionalOnProperty
Creates bean only if specified property exists or matches value. Example: @ConditionalOnProperty(name="feature.enabled", havingValue="true"). Use for feature toggles. Can check multiple properties. Enables conditional configuration. 📝
@ConditionalOnClass
Creates bean only if specified class is on classpath. Example: @ConditionalOnClass(DataSource.class). Used in auto-configuration. Enables library-specific beans. Checks class availability at runtime. 📚
@ConditionalOnMissingBean
Creates bean only if no bean of specified type exists. Provides default implementation. Allows user override. Example: @ConditionalOnMissingBean(DataSource.class). Common in auto-configuration for fallback beans. 🔄
@ConditionalOnBean
Creates bean only if specified bean exists in context. Establishes bean dependencies. Example: @ConditionalOnBean(DataSource.class). Use when bean requires another bean to function. Ensures proper initialization order. 🔗
🌈 Lifecycle & Events
@PostConstruct
Executes after dependency injection is complete. Initialization logic after bean construction. Called only once. Use for setup that requires injected dependencies. Example: load cache, validate configuration. Part of JSR-250. 🎬
@PreDestroy
Executes before bean is removed from container. Cleanup logic before destruction. Called during shutdown. Use for releasing resources, closing connections. Example: flush buffers, save state. Part of JSR-250. 🧹
@EventListener
Listens to application events. Method parameter type determines event type. Example: @EventListener(ApplicationReadyEvent.class). Enables event-driven architecture. Can be async with @Async. Decouples components. 📡
🔧 Actuator & Monitoring
@Endpoint
Creates custom Spring Boot Actuator endpoint. Exposes operational information. Example: @Endpoint(id="custom"). Use with @ReadOperation, @WriteOperation. Access via /actuator/custom. Enables custom monitoring and management. 📊
@ReadOperation
Defines GET operation for actuator endpoint. Returns endpoint data. Example: @ReadOperation public Map getData(). Read-only access. Used for retrieving metrics, health info, configuration. 👀
@WriteOperation
Defines POST operation for actuator endpoint. Modifies endpoint state. Example: @WriteOperation public void updateConfig(). Use for administrative actions. Requires proper security. Enables runtime configuration changes. ✍️
